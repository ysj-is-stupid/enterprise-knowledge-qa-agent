# 企业知识问答 Agent：最终状态与提交清单

## 1. 当前结论

项目代码、规定目录、必需文档、实际输出、结构化 Trace 和自动化测试已经完成。核心业务链路及六类必须验收场景均有可执行验证；真实 DeepSeek 模型还完成了长对话与跨文档证据两类扩展路径。

当前没有阻塞提交的功能缺陷。正式交付只差提交者提供准确题号，并执行 Git/GitHub 交付动作。本地 Git 元数据已经存在，但按提交者要求尚未创建首个 commit、配置 remote 或推送。

## 2. 已完成能力

- CLI 输入问题、可选对话历史、部门和规则生效基准日。
- 原生单动作 ReAct 循环；模型每次只能从动作白名单中选择一个动作。
- `search_docs` 混合检索与 `read_doc` 原文片段读取。
- 根据搜索结果继续检索、补读原文、请求澄清或结束。
- 明确答案、资料不足、未裁决冲突、工具失败和执行上限的结构化状态。
- 文档 ID、版本日期、有效期、片段 ID 和逐字原文引用。
- fail-closed 逐句支持证书、语义事实校验和回答自相矛盾拦截。
- 规则冲突检测、适用范围展示及保守的显式覆盖裁决。
- 部门 ACL 和生效期在相关度计算前过滤，防止越权和未来规则泄漏。
- 最近消息原文与相关旧消息原文组成的可溯源长对话记忆。
- 跨章节、跨文档依赖证据的递归补读、完整引用和循环校验。
- 工具失败指数退避、调用次数上限和上限触发时的部分信息保留。
- 事务型 SQLite 反馈、幂等写入、自动归因、统计和 JSONL 原子迁移。
- 离线 Mock 与 OpenAI-compatible/DeepSeek 真实模型使用统一工具调用信封。

详细设计见 [06-detailed-design.md](06-detailed-design.md)，工程取舍见 [02-solution.md](02-solution.md)。

## 3. 验收与验证材料

六类必须验收场景均提供输入、实际输出和 Trace：

1. 明确答案：`completed`。
2. 文档冲突：`needs_clarification`，列出 D01/D02 原文与适用范围，不擅自选边。
3. 资料外问题：`insufficient_evidence`，无事实声明和引用。
4. 改写后的相似问题：`completed`。
5. 上下文追问：`completed`，Trace 保留独立查询。
6. 工具失败：`tool_error`，重试后仍失败时拒绝凭记忆作答。

扩展真实模型路径：

- 长对话追问：从最近窗口以外召回相关历史原文并完成回答。
- 跨文档证据：实际执行 `search_docs → read_doc(D20) → read_doc(D21) → finish`，同时引用两份文档并生成两份支持证书。

验证结果：

- 自动化测试：69 项通过，最近记录为 `Ran 69 tests in 0.612s`。
- 真实 DeepSeek 路径：六类必验 + 两类扩展，共 8 条，状态均符合预期。
- 编译检查通过。
- 已配置 API Key 逐字扫描：0 命中；私钥头、常见 `sk-` 与 Bearer Token 形态：0 命中。宽泛的“凭据赋值”规则只命中 `tests/test_smoke.py` 中用于验证脱敏的 `do-not-print` 测试占位值，经人工核对不是真实凭据。

完整结果和边界见 [03-evaluation.md](03-evaluation.md) 与 [07-validation.md](07-validation.md)；原始测试输出见 [test-results.txt](../examples/test-results.txt)。

## 4. 正式提交前剩余事项

以下是交付动作，不是功能缺陷：

1. 填写准确题号。
2. 检查暂存文件，确认 `.env`、`.venv/`、`runtime/` 和 IDE 文件未进入版本控制。
3. 创建首个也是最终交付 commit。
4. 创建或关联 GitHub 仓库并推送。
5. 记录 GitHub URL 和最终 commit SHA。
6. 若使用私有仓库，为指定评审账号授予只读权限。

建议提交信息模板：

```text
题号：<待提交者填写>
GitHub URL：<待推送后填写>
最终 commit SHA：<待提交后填写>
```

## 6. 诚实边界

- 8 条真实模型路径使用合成资料，证明接入和这些场景中的动态动作可运行，不证明生产环境总体质量。
- 复杂自然语言语义不是形式化证明；成功答案通过收紧输出契约，只接受可逐句复核的原文或程序定义的等价变换。
- 长对话采用确定性的原文检索记忆，不生成摘要；大规模真实对话的召回率仍需统计评测。
- 反馈默认保存在本地 SQLite，尚未接入远程分析或运营系统。
- 跨片段依赖已经支持跨文档，但依赖关系必须由资料元数据显式声明，系统不会自动推断任意隐含条款关系。
- ACL 的部门身份由可信调用上下文提供，尚未接入企业身份系统。

## 7. 提交前复核命令

```powershell
$env:PYTHONPATH = (Resolve-Path "src").Path
python -m compileall -q src tests
python -m unittest discover -s tests -v
python -m enterprise_qa_agent.cli health --json
```

不要把本地 `.env`、运行数据库、虚拟环境或真实企业数据提交到仓库。
