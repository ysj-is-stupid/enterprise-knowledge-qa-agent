# AI 辅助使用说明

## 1. 使用方式

本项目通过 Codex 协助完成需求整理、技术选型、方案设计、代码实现、测试、缺陷定位和文档编写。整个过程采用阶段闸门：每个阶段完成后停止，由提交者审阅并明确同意后才进入下一阶段。

## 2. AI 辅助内容

AI 参与了以下工作：

- 将题目约束整理为可验证的需求和成功标准。
- 比较原生 ReAct 与 Agent 框架的取舍。
- 设计数据结构、动作协议、工具协议和执行状态机。
- 编写 Python 工程骨架与核心实现。
- 构造合成制度、FAQ 和同义词资料。
- 编写自动化测试和故障注入路径。
- 运行 CLI，生成实际输出与 Trace。
- 接入真实 DeepSeek 模型，分析并修复兼容协议差异。
- 分析检索误召回、临时目录权限等失败并修改实现。
- 编写 README、评估、AI 使用和复盘文档。

## 3. 提交者的输入与修改要求

提交者没有把实现完全交给一次性自动生成，而是提出并审阅了关键设计方向：

1. 要求按“技术选型、方案初设、详细设计、工程骨架、核心链路、验收与文档、全量验证”分阶段推进。
2. 要求每个阶段完成后汇报，未经确认不得进入下一阶段。
3. 提出输入预处理、问题路由、混合检索、证据校验、冲突检测、分支决策和逐条引用校验建议。
4. 要求对未采纳建议说明原因，而不是机械照搬。
5. 接受将路由限制为分类而非直接回答，避免绕过检索。
6. 最终将“任意自然语言语义证明”收敛为可审计的逐句证明契约：成功声明只能复制原文分句或使用明确定义的事实等价变换。

这些要求直接改变了最终架构：加入独立查询、轻量路由、冲突检查带、声明—证据结构和阶段式验证材料。

## 4. 个人修改与判断

可归因于提交者的主要修改不是逐行手工改代码，而是对 AI 初始方案施加业务与工程约束：

- 明确要求处理上下文指代，而不是直接检索当前短句。
- 强调冲突资料必须查证和中断，不能依据日期擅自裁决。
- 强调工具失败重试后必须拒绝凭记忆作答。
- 强调每一条事实需要原文支持，并促成结构化事实声明设计。
- 要求所有阶段讨论和取舍落入仓库文档。

如果提交者在最终提交前继续直接修改代码或参数，应在本节追加具体文件、修改内容和原因。

## 5. 验证方式

AI 生成的内容没有只通过阅读确认，而是执行了以下验证：

- `python -m compileall -q src tests`
- `python -m unittest discover -s tests -v`
- 六类 CLI 场景实际运行并保存输出。
- 替换知识库原文后重新运行相同问题。
- 注入工具失败并检查模型后续动作。
- 使用故意提前完成、伪造证据和提交无支持声明的测试模型攻击完成守卫。
- 检查公共配置中不包含 API Key 值。
- 使用真实 DeepSeek 模型运行六类必验场景及长对话、跨文档证据两类扩展路径，并保存脱敏输出与 Trace。

当前结果为 69 项测试全部通过；新增测试还覆盖逐句支持证书、高相似度条件篡改、引用洗白、跨文档证据链及其 ACL/有效期防泄漏、冲突终止状态守卫、部分结果保留、指数退避、统一工具调用协议、DeepSeek 兼容行为、可溯源长对话记忆、回答长度、SQLite 反馈事务和 JSONL 迁移。

## 6. AI 输出被修改的实例

### 6.1 路由设计

初步建议包含问题路由。最终限制路由器不能直接回答业务事实，所有业务知识问题必须检索，降低误路由后凭记忆回答的风险。

### 6.2 引用证明边界

“程序证明任意自然语言释义”不可实现。最终采用 fail-closed 契约：claim 逐句映射到绑定原文，仅允许程序定义的单位等价变换；输出支持证书，无法证明的复杂释义不得以 `completed` 返回。这样证明的是受限答案语言中的证据支持关系，而非开放式自然语言蕴含。

### 6.3 检索评分

第一版检索归一化导致公共词误召回。实际运行发现问题后，改为查询词项权重上限归一，并限制冲突带启用条件。修复由回归测试证明。

### 6.4 替换资料测试

第一版测试写入系统临时目录，在受控环境失败。最终增加内存知识库入口，以无文件副作用方式验证答案会随资料变化。

## 7. 边界与责任

- 离线 Mock 的输出不能当作真实模型效果结论；8 条真实模型合成路径也不能外推为生产质量评估。
- 合成制度不能当作真实企业政策。
- AI 生成的实现仍需提交者阅读、运行并对最终提交负责。
- 真实密钥仅保存在被忽略的本地 `.env` 中，未写入仓库、输出、Trace 或文档；项目只使用合成制度，不含隐私数据。
